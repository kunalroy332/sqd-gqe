# AGENTS.md

This file provides guidance to agents when working with code in this repository.

## Project Overview

This is a **Python template repository** designed for creating new Python packages at IBM. It provides a standardized project structure with modern Python tooling and development workflows.

**Key Technologies:**
- **Python 3.11+**: Minimum required version
- **uv**: Fast Python package manager and virtual environment manager
- **Ruff**: Fast all-in-one linter and formatter (replaces pylint, black, flake8, isort)
- **setuptools_scm**: Git-based versioning (no manual version files)
- **towncrier**: Structured changelog management
- **pytest**: Testing framework
- **pre-commit**: Automated code quality checks

**Template Usage:**
This is a template repository. To use it for a new project, perform find-and-replace for:
- `Project Name` → Your project's display name
- `project_name` → Your Python package name (snake_case)
- `project-name` → Your package name for PyPI (kebab-case)

## Project Structure

```
project_name/          # Main Python package (rename this)
├── __init__.py
└── _version.py        # Auto-generated by setuptools_scm

test/                  # Test directory
└── conftest.py        # Pytest configuration and fixtures

tools/                 # Development utilities
└── verify_headers.py  # Copyright header verification script

changelog.d/           # Towncrier changelog fragments
```

## Building and Running

### Prerequisites

This project uses **uv** for fast, reliable Python package management. Install uv first:

```bash
# macOS and Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"

# Or via pip
pip install uv
```

### Installation

**Standard installation:**
```bash
uv pip install .
```

**Development installation (editable mode with dev dependencies):**
```bash
uv pip install -e ".[dev]"
```

**Using uv sync (recommended for development):**
```bash
uv sync --all-extras
```

### Virtual Environment Management

uv automatically manages virtual environments:

```bash
# Create a virtual environment
uv venv

# Activate it (Linux/macOS)
source .venv/bin/activate

# Activate it (Windows)
.venv\Scripts\activate
```

You can also run commands directly without activating using `uv run`:
```bash
uv run python script.py
uv run pytest
```

### Testing

Run tests with pytest:
```bash
uv run pytest
```

Or run directly if you've activated a virtual environment:
```bash
pytest
```

Tests are located in the `test/` directory.

### Linting and Formatting

**Manual linting:**
```bash
uv run ruff check .
```

**Auto-fix issues:**
```bash
uv run ruff check . --fix
```

Or run directly if you have ruff installed globally or in an activated environment:
```bash
ruff check .
```

**Recommended:** Configure your IDE to run ruff on save (see VSCode setup in README).

## Development Conventions

### Code Quality Standards

1. **Ruff Configuration** (`pyproject.toml`):
   - Line length: 100 characters
   - Target: Python 3.11
   - Enabled rules: pycodestyle (E), pyflakes (F), isort (I)
   - `__init__.py` files: Unused imports (F401) and import order (E402) are allowed

2. **Copyright Headers**: All Python files must include the IBM proprietary header:
   ```python
   # This code is part of the Project Name project.
   #
   # This is proprietary IBM software for internal use only, do not distribute outside of IBM
   # Unauthorized copying of this file is strictly prohibited
   #
   # (C) Copyright IBM 20XX.
   ```
   - Header verification runs automatically via pre-commit hooks
   - Manual verification: `python tools/verify_headers.py`
   - Files can be excluded using the `--omit` flag with glob patterns

3. **No PEP 263 Encoding Declarations**: Do not include `# -*- coding: utf-8 -*-` or similar encoding specifications (Python 3 defaults to UTF-8)

### Version Management

Versions are managed entirely through **git tags** using setuptools_scm:

1. Ensure you're on the main branch
2. Create an annotated tag: `git tag -a 1.2.3`
3. Push tags to origin: `git push --tags`

The version is automatically generated in `project_name/_version.py` (never edit this file manually).

### Changelog Management

Use **towncrier** for structured changelog entries:

1. **Create a changelog fragment** for each PR:
   ```bash
   echo "Added a new particle weighting system." > changelog.d/42.feature.rst
   ```

   Fragment naming: `<PR_number>.<type>.rst`

   Common types: `feature`, `bugfix`, `doc`, `removal`, `misc`

2. **Build the changelog** before releasing:
   ```bash
   uv run towncrier build --yes
   ```

### Pre-commit Hooks

Pre-commit hooks automatically run on `git commit`.

**Note:** pre-commit is installed in the Python virtual environment, so all pre-commit commands should be run via `uv run`:

**Setup (one-time):**
```bash
uv run pre-commit install
```

**Manual execution on all files:**
```bash
uv run pre-commit run --all-files
```

**Update hooks to latest versions:**
```bash
uv run pre-commit autoupdate
```

**Hooks configured:**
- Trailing whitespace removal
- End-of-file fixer
- YAML validation
- Copyright header verification
- Ruff linting and formatting
- Towncrier changelog fragment validation

## CI / Continuous Integration

CI is GitHub Actions on github.ibm.com. There is no IBM Cloud One Pipeline / `.pipeline-config.yaml` and no tox here — those have been removed from this template.

- `.github/workflows/tests.yml` runs `uv sync --all-extras` + `uv run pytest -v` on the `ibm-x86-64-small` IBM-hosted runner. Triggers: push to `main`/`tests`, any pull request, manual dispatch.
- `.github/workflows/manual.yml` is a placeholder "hello world" workflow, not real CI.
- ibm-q-research repos typically have `allowed_actions: local_only`, which **rejects marketplace actions** (`actions/checkout`, `astral-sh/setup-uv`, etc.). The workflow is therefore pure shell: `git clone` to check out, `curl ... | sh` to install uv. Do not "modernize" it back to `uses:` blocks without first verifying the policy:
  ```bash
  GH_HOST=github.ibm.com gh api /repos/<org>/<repo>/actions/permissions
  ```
- **Private deps**: this template has no private dependencies. If you add private `github.ibm.com/ibm-q-research/*` deps, the default `${{ github.token }}` is scoped to the current repo only and `uv sync` will fail with `remote: Repository not found`. Add an auth step that consumes one of:
  - secret `INTERNAL_REPO_TOKEN` — a PAT with read access on the dep repos, OR
  - secret `INTERNAL_SSH_KEY` — a PEM private key whose public counterpart is registered as a deploy key on each dep repo.

  See `ibm-q-research/proglib`'s `.github/workflows/tests.yml` for a worked example of both paths.

### Monitoring CI

The `gh` CLI must be pointed at github.ibm.com explicitly via the `GH_HOST` env var (`gh run list --hostname` does not exist):
```bash
GH_HOST=github.ibm.com gh run list -R <org>/<repo>
GH_HOST=github.ibm.com gh run view <id> -R <org>/<repo> --log-failed
```

## Important Notes for Agents

- **This is a template**: When working with this repository, remember it's meant to be copied and customized for new projects
- **Copyright headers are mandatory**: All new Python files must include the IBM proprietary header
- **No manual versioning**: Never manually edit version numbers; they're managed by git tags
- **Changelog fragments required**: For any feature/bugfix work, create appropriate towncrier fragments
- **Pre-commit hooks will block commits**: Ensure code passes all checks before committing
- **IBM Internal Only**: This is proprietary IBM software not for external distribution
